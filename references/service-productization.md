# 服务产品化：把模糊能力变成可购买、可交付的单位

**触发**：用户卡在服务、课程、咨询、设计、制作、代运营、报价或交付，并且说不清客户到底买走什么、如何验收、为什么复购。

**暂定判断**：卡点可能不是“缺创意”，而是缺少稳定的交易与交付单位。先验证客户任务和最小服务规格，再决定是否标准化、扩张或平台化。

## 一、先确认客户任务

产品化之前先回答：

- 谁在什么触发场景下购买？
- 他要完成什么任务或降低什么风险？
- 现有替代方案是什么，哪里不满意？
- 谁付款、谁使用、谁验收，是否为同一人？
- 哪个结果可承诺，哪个结果只能尽力而不能保证？

如果客户任务尚未验证，不要直接做完整服务体系。先用访谈、预售、手工交付或样品验证。

## 二、最小服务规格

| 槽位 | 要回答的问题 | 缺失的后果 |
| --- | --- | --- |
| 对象与边界 | 为谁解决哪一类问题，明确不做什么 | 所有需求都接，无法复用 |
| 计价单位 | 按次、周期、项目、席位、产出或阶段收费？ | 无法比较价格与成本 |
| 客户输入 | 启动前客户必须提供什么、何时提供？ | 项目等待、返工、责任争议 |
| 服务动作 | 关键步骤、责任人和响应时间是什么？ | 质量依赖个人临场发挥 |
| 交付物 | 客户最终拿到哪些可指认产物？ | 只能感知“花了时间” |
| 验收标准 | 范围、质量、时效和修改次数如何判断？ | 交付无限扩张 |
| 效果证据 | 领先信号和结果信号是什么？ | 无法证明价值或改进 |
| 异常处理 | 延迟、失败、退款、换人、数据与版权如何处理？ | 风险在成交后集中爆发 |

## 三、通用规格模板

```text
服务名称：动词 + 对象 + 可观察结果
适用客户/触发场景：
不适用与范围边界：
单位：____ 次 / 周期 / 项目 / 产出 / 席位
客户输入：
关键步骤与里程碑：
交付物：
验收标准：质量 / 时效 / 修改范围
效果证据：领先信号 / 结果信号
价格：基础项 / 可选项 / 超范围项
风险处理：延期 / 失败 / 退款 / 数据 / 版权
复购或下一阶段触发条件：
```

先填出一个可手工交付的版本，不要一开始追求覆盖所有客户。

## 四、三类常见反模式

| 反模式 | 症状 | 修正方向 |
| --- | --- | --- |
| 卖投入 | 强调花了多少时间、用了多少工具 | 改为客户可验收的产出与边界 |
| 卖概念 | “定制化、陪伴式、全案、增长赋能” | 拆成具体动作、产物和判据 |
| 卖不可控结果 | 承诺销量、排名、治愈、必然成功 | 区分可控交付与受外部因素影响的结果 |

按时计费并非天然错误。探索性、高不确定或客户频繁改变范围的工作，按时或按阶段计费可能更合理；关键是让范围、记录和风险分配清楚。

## 五、定价：先守底线，再看锚点

1. **成本底线**：履约、沟通、返工、获客、税费和风险准备金。
2. **替代锚**：客户当前替代方案的总成本，包括时间和切换风险。
3. **市场锚**：可比服务的价格，但要说明范围和质量差异。
4. **价值锚**：服务若成功，为客户增加或避免的价值；不可把不受控价值全算成自己的价格。

选择固定价、按时、按阶段、订阅或绩效计费时，检查谁承担需求变化、结果归因和现金流风险。绩效分成需要可归因、可审计、可结算和足够信任；冷启动阶段通常先用简单交易验证。

## 六、验证而不是脑补

在一个自然反馈周期内验证最危险的假设，例如：

- 客户是否能复述自己买到什么；
- 是否愿意按该单位付费或支付定金；
- 两个执行者能否按同一规格交付接近结果；
- 交付后客户能否看到预先约定的证据；
- 实际工时、返工和毛利是否在可承受区间。

样本小的时候只做方向性判断，不把少数好评当成需求已验证。

## 七、何时平台化

默认顺序是：客户任务验证 → 最小服务规格 → 小样本交付 → 找到重复模式 → 再决定标准化或平台化。

平台化前至少要知道：供需两侧的稳定单位、匹配变量、质量判据、失败处理和单位经济。若平台本身是验证供需、合规或协作所必需的基础设施，允许先做最小平台，但明确它验证的假设和停止条件。
